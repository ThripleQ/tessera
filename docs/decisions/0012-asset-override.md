# 0012 外观开放：目录覆盖，而不是新的内容类型

## 背景

三层开放里前两层已经成立：内容开放（TOML → `content.pack.json`）和行为开放
（L3 钩子 + L4 组件/系统，ADR 0007 / 0011）。第三层**外观开放**在 ADR 0003 只
验证了通道（无头下能读绝对路径 PNG、能枚举磁盘目录、能运行时编译 GDScript），
功能一直没做：`model.mesh` 只能取 `contract/registry.py` 里 7 个内置 id，
形状由 `mesh_lib.gd` 的程序化几何钉死，`docs/status.md` 把它记为"最后一块架构洞"。

用户 2026-11-14 拍板：资源可以用，且优先网上找现成的（CC0 / 可商用）。
于是"像原神的角色"的路径 = 现成风格化模型 + 现成动画 + 卡通着色，
不再自己造美术资产。这一步先把**换模型**这条路打通。

## 决定

1. **外观开放走目录覆盖，不引入新 `kind`、不改契约、不改编译器。**
   一个 mod 目录里放 `assets/meshes/<网格 id>.gltf`（或 `.glb`），
   那个网格就换成文件里的几何；没放文件的网格回退到内置程序化几何。
   这跟 MC 资源包一致：**资源包只覆盖已有槽位，不声明新 id**。

2. **文件名就是 id，路径由目录枚举出来，内容里不写路径。**
   于是天然不存在 `../../` 逃逸 —— `DirAccess.get_files()` 返回的是文件名，
   不含路径分隔符。`data` 级资源包默认放行也不会读到 mod 目录之外的任何东西。
   拼错文件名会被记成"孤儿资源"报出来，而不是静默失效。

3. **`game/scripts/world/assets.gd` 是"问几何"的唯一入口。**
   `plan` / `chunk` / `world_root` / `solids` / `player` / 探针全部改走
   `ASSETS.mesh()` 与 `ASSETS.triangles_of()`；`mesh_lib.gd` 退成内置兜底实现。
   覆盖优先，回退内置。材质仍由 `mesh_lib` 提供（这一轮不动材质）。

4. **只有已启用的 mod 参与覆盖，后加载的压过先加载的。**
   未授权的 mod 连外貌也不该生效 —— 授权闸门要么全开要么全关，半开等于绕过去。
   顺序沿用 `mod_units`（按 id 排序，玩家装的目录在仓库自带之后）。
   资源包没有 `.gd`，是 `data` 级，**不需要 `--trust`**：换外貌不等于运行任意代码。

5. **坏文件不静默回退。** 解析失败 / 文件里没有三角形 / 孤儿文件名都记进
   `problems()`，由无头自检和第 11 步探针判红。"装了却什么都没发生"是最难查的问题。

6. **数字不许骗人。** `schema.meshes` 里的三角形数是**内置程序化几何的规划值**，
   覆盖后不适用（几何来自 mod 目录里的文件，编译期看不到它改没改）。
   自检对未覆盖项继续做「契约 vs 实测」对拍；对覆盖项要求运行时实测 > 0，
   并把实测合计打印出来。世界的负载统计（`plan` / `chunk` / `perf`）一律按实测算。

7. **运行时加载用 Godot 内置 `GLTFDocument`，从磁盘绝对路径读。**
   纯 CPU，无头下可用（实测：外部 `.gltf` → `ArrayMesh`）。
   `generate_scene()` 造出的节点不在场景树里，必须显式 `free()` ——
   否则退出时泄漏一串 RID，被 `no_engine_errors()` 判成引擎报错。

一句话：**引擎不再决定任何东西长什么样，只决定"去哪个文件夹问"。**

## 被否掉的选项，以及为什么

- **`.pck` + `load_resource_pack()`**：ADR 0003 已否。需要导出工具链才能产出 pck，
  资源包的本质就是文件夹，玩家能直接看能改。
- **让 mod 用 `kind="mesh_spec"` 声明新网格 id**：那是"加一种形状"，不是"换外貌"。
  混进这一层会让默认放行的 `data` mod 也能改契约边界；真要做应该像 L4 那样
  走编译器 + `extensions` 容器，单独一个决定。
- **把外部模型的三角形数写进契约 / 让作者手写**：文件不在仓库里，编译期不知道它
  有没有被换掉，手写必然失真。改成运行时实测 + 打印。
- **坏文件静默回退内置几何**：玩家会以为资源生效了，实际看到的是原来的箱子。
- **让内容里写资源文件路径**：字符串里能塞 `../`，而 `data` 级 mod 默认放行，
  等于给了一条读任意文件的路。改成目录枚举，堵在源头。
- **这一轮顺手把贴图也做了**：贴图要按网格绑定到共享材质 / MultiMesh 合批单位，
  而配色按内容走，两者单位不一致，是另一个独立决定。混在一笔里会让
  "一件事一提交"和探针断言都失去边界。见 `docs/status.md` 下一步。

## 什么情况下应该推翻这个决定

- **现成资源普遍带蒙皮 / 复杂节点层级，静态网格提取不够用**：改成加载整个场景
  实例并保留 AnimationPlayer，那时"资源层"要升级成"资源 + 动画层"。
- **需要按配色换贴图，而不只是按网格**：MultiMesh 的合批单位是 mesh，
  贴图单位若变成 palette 就得拆批，先重做合批预算再谈覆盖。
- **导出包里 `GLTFDocument` 不可用**（P6 必须验）：改成构建期预导入成 `.pck`，
  或自带一个纯文本 OBJ 解析器（现成低模包常带 OBJ，且不依赖引擎导入器）。
- **覆盖数量多到明显拖慢启动**：加预加载清单 / 缓存索引，不能靠
  "让玩家少装几个 mod" 解决。
