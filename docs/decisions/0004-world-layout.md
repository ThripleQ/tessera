# 0004 世界怎么排布

## 背景

契约里 `room` 组件只声明了尺寸（`size_x` / `size_z`）和是否有烘焙光，**没有坐标**。
也就是说内容只说了"有哪些房间、多大、里面放什么"，没说"房间在世界里的哪"。
但引擎必须把房间摆到某个地方，否则它们会全部叠在原点。

## 决定

**房间按内容 id 的字典序沿 X 轴依次排列，间隔 12 米；一个房间就是一个渲染块。**

1. 排序用 id 而不是文件系统顺序，保证同一份内容在任何机器上排出同一个世界。
2. 一块一房间——契约里 `room` 组件的原话就是"分块流式加载以它为单位"。
3. 房间之间留 12 米走道，走道没有地板，所以引擎额外铺一块**世界底板**托底。
   底板纯视觉，不参与玩法、不加碰撞。它是引擎的兜底，不是内容。
4. 块内的实例按网格分组，同网格合成一个 `MultiMesh` → 一次提交。

## 被否掉的选项，以及为什么

| 选项 | 为什么否 |
|---|---|
| 让内容声明房间坐标 | 那要先改契约和所有内容文件。现在没有"世界地图"这个概念，硬加会先入为主地定死布局方式 |
| 按房间尺寸自动拼图（矩形装箱） | 装箱结果依赖算法版本，同一份内容换个版本世界就变了，**不可复现** |
| 房间互相贴紧（gap=0） | 房间尺寸不同（32×32 与 48×40），贴紧后边界参差，反而更难看 |
| 每块用固定 32 米网格切分 | `room` 已经定义了尺寸，再切一层等于两个真相，改一个忘一个 |

## 什么情况下应该推翻这个决定

- **内容需要精确控制布局时**（比如做一张手工设计的地图）：新增 `world` 这个 kind，
  在里面声明房间坐标与旋转，本 ADR 的"按序排列"降级为默认值。
- **房间多到一屏放不下时**：沿 X 排成一条线会让世界变成一根长条，玩家永远只看到
  前后两个房间。届时改成按 `(x, z)` 二维排布，或引入房间连接图。
- **出现房间之间的门/通道时**：走道宽度成为玩法参数，`ROOM_GAP` 要从常量挪进内容。
- **需要大地图流式加载时**：一室一块的粒度太粗（一个 48×40 的房间不能只加载一半），
  块要按固定尺寸切，本 ADR 第 2 条作废。
