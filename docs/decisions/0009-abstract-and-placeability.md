# 0009 内容的存在性：`abstract` 与"能不能摆"

- 状态：已实现
- 日期：2026-11-14
- 影响面：`contract/registry.py`（`TOP_FIELDS`）、`tools/contentc.py`、
  `game/scripts/content/pack.gd`、`game/scripts/hooks/api.gd`、`game/scripts/ui/spawn_menu.gd`

---

## 背景

一句话：**"这条内容能不能单独出现在世界里"，以前是一个只写在注释里的规则。**

`content/enemy/base_undead.toml` 的 `doc` 里写着"它本身不会被摆进世界，只作为 extends 的起点"。
引擎不读 `doc`。于是生成菜单做完，第一项就是「亡灵（基类）」，点下去必然失败 ——
一个看起来完全正常的 bug，因为那个东西长得和其他内容一模一样。

同一个坑在这份内容里出现过两次：`pack.spawnables()` 的注释声称"基类靠 tags 里的
`abstract` 排除"，而内容里**没有任何人**往 tags 里写这个词。

---

## 决定

1. **`abstract = true` 是一个正式的顶层字段**，进 `TOP_FIELDS`（带类型 `bool`），
   由编译器校验。它不是 tag。
2. **它不继承。** 给基类标上它，子类照旧是具体内容。
3. **"摆出来会怎样"只看一条数据**：`collider.dynamic`。
   `true` → 刚体；`false`（或没有 collider）→ 钉住的静态物。引擎不看 id、不看名字（铁律 2）。
4. **`api.spawn` 返回 `{ok, handle, dynamic, reason}`**，不再用 `0 == 失败`。
5. **`abstract` 不能被 patch 改**，因为 patch 的语义是"改数值"，而这个字段决定"还存不存在"。

三条硬检查（`check.sh` 会失败）：

| 检查 | 在哪 | 后果（如果没拦） |
|---|---|---|
| 抽象内容不能被房间的 `spawner` 指向 | `contentc` 语义检查 | 房间里站着一个半成品，不报错 |
| 抽象内容不进生成菜单 | `pack.spawnables()` + 无头自检 | 玩家点必失败，以为菜单坏了 |
| `abstract` 不继承 | `contentc` 解析 + 编译器自测 | 给基类标一次，**一整类内容从世界里消失**，无声 |

### 为什么 `spawn` 不再返回 int

静态物没有物理身份 —— 它没有 handle、不参与模拟、不该被抓取。所以
「放下了」和「没放下」在一个 `int` 里没法区分（都是 0）。

而生成菜单**必须**能说出是哪一种：一个只会说"失败"的菜单，会让人以为整个功能坏着。
`reason` 是给人看的一句话，会被原样显示在状态栏 —— 错误码不行，
玩家读不懂 `ERR_SPAWN_BUDGET`。

---

## 被否掉的选项，以及为什么

| 选项 | 否掉的理由 |
|---|---|
| 用 `tags = ["abstract"]` | tags 是**内容之间**的约定（mod 可以往里面加任何东西），而"能不能出现"是**引擎的行为**。把引擎行为挂在一根内容字符串上，写错一个字母的后果是基类被摆进世界 —— 而且看起来完全正常。tag 也没有类型，没有校验，没有补全 |
| 让 `abstract` 继承（子类显式写 `false` 取消） | 一个"默认值为 true 的继承属性"是纯陷阱：忘了写 `false` 的后果是一整类东西静默消失。而且所有子类都要写一行没意义的东西 |
| 让 `spawn` 只造刚体，静态物另开一个 `place()` | 那要求调用方**先知道**这条内容会不会动 —— 于是在菜单里又多出一处"按内容判断"的逻辑。引擎按数据判断（铁律 2），调用方不该知道 |
| 静态物不进存档 | 那"从菜单放下的东西"关窗就没了，与 ADR 0008 的承诺直接矛盾。世界用 `world.props` 把它和"房间自带的障碍"分开记，存档只抄 `props` |
| 给静态物也发 `entity.spawn` | 那个钩子承诺的是"一个新的**刚体**进来了"，mod 会拿 handle 去调 `api.pos()`。对静态物发它等于朝契约撒谎 |

---

## 什么情况下应该推翻这个决定

- **如果哪天出现"半抽象"内容**（比如"能摆但只能在房间里摆"）：那说明需要的是
  一个三值的存在性字段，而不是布尔。届时改成 `placement = "world" | "room" | "never"`，
  并且**照样不能继承**。
- **如果 `api.spawn` 的返回值要再加字段**：加字段可以，改语义不行。已经有人
  （未来的 mod）会写 `if r["ok"]`。真要改，就出 `api_version = 2` 并行一段时间。
- **如果静态物变成可被拾取/推动**：那它就有了物理身份，`props` 和 `bodies` 的分界
  会失效。那时候应该先回答"静态物到底是不是一种刚体"，再决定要不要合并两个列表。
