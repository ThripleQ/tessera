# ADR 0018：受击反馈分三层 —— 看得见（UI）、摸得着（物理）、挨打之后会怎样（内容）

- 日期：2026-11-21
- 状态：已落地（第二十轮）
- 相关：ADR 0016（FPS 训练场）、ADR 0017（硬切 + 相位对齐）

## 背景

第 17 步验收了"手里的枪能打死东西"。但"能打死"和"打中了对方知不知道"是两件事。

玩家开枪、打中一只怪，**画面上什么都没变** —— 血条可能动一下（如果有），
但那只怪不会退、不会愣、准心也不会闪。这时候玩家的合理推断是"我打偏了"，
于是第二枪更用力，第三枪更慌。**反馈缺失比打得不准更伤手感**：打得不准会让人调整，
反馈缺失只会让人怀疑自己的准头。

所以这一轮做的事是：让"打中了"这件事，在**不用挪视线**的前提下被确认。

## 决定

### 1. 受击反馈分三层，各管各的

| 层 | 做什么 | 载体 | 谁写 | 谁读 |
|---|---|---|---|---|
| 看得见 | 准心上闪一个 X | UI（准心） | 枪发信号 → 装配层 → 准心 | 玩家眼睛 |
| 摸得着 | 挨打会退 | 物理（刚体速度） | `vitals` 写 meta → `locomotion` 读 | 玩家眼睛 |
| 挨打之后会怎样 | 会退多少、会愣多久 | **内容**（`hit_react` 组件） | 内容作者 | 两个系统都读 |

**"挨打之后会怎样"是内容，不是代码里的常量。** 理由：同一个"被打一下"，
对一只玻璃塔和一头牛应该完全不同 —— 血量可以一样，手感不能一样。
写进内容，改数值不用改代码，也不用重编引擎侧逻辑。

### 2. 契约组件 `hit_react`

```
knockback: float 0..50   被打中时向后退多少 m/s
stun:      float 0..5    被打中后愣住多少秒（期间不走）
```

两条都写 0（默认）= "打了跟没打一样"。这是**默认**而不是"必须显式配置"——
没配 `hit_react` 的怪不会报错，只是打上去没反应。

### 3. 状态放在刚体的 meta 上，两个系统互不认识

```
vitals.damage(node, amount, dir)  →  写 rb.set_meta("hit_react_state", {...})
locomotion.step()                  →  读 rb.get_meta("hit_react_state")
```

`vitals` 不知道 `locomotion` 存在，`locomotion` 不知道 `vitals` 存在。
它们只通过**组件**（内容里写的）和 **meta**（运行时状态）交流。

这正是契约 `check_system_order` 精神在系统层的延续：写状态的系统和读状态的系统
不该互相 import，因为一旦互相 import，"谁先跑"就变成了硬依赖。

### 4. 不能直接写刚体速度做击退

最容易想到的实现是：`damage()` 里直接 `rb.linear_velocity = -dir * knockback`。
**这行代码看起来对，但没有任何效果。** 因为 `locomotion.step()` 每帧无条件写
`rb.linear_velocity` —— 下一帧就被抹平了。玩家的观感是"打了没反应"，
而且调试时速度是"写上去又变回去"，极难定位。

所以击退必须走**速度计算**：击退是速度计算里的一项，不是对速度的一次性赋值。

### 5. 推力的衰减公式：存初始值，算当前值

```
meta 里存:  push0（初始推力）、stun（剩余僵直）、total（总僵直）
当前推力  =  push0 × (stun / total)     ← 在 locomotion 里算
```

**不能每帧把当前推力乘一次剩余比例。** 那样的衰减是平方级的
（第一帧 ×0.9，第二帧 ×0.81，第三帧 ×0.73…），0.35 秒后推力几乎归零，
怪被"推了一下"就停住 —— 观感是"抖了一下"，不是"被推退"。

存初始值、每次重算，是线性衰减。实测：挨一枪往后退的速度峰值 **2.38 m/s**，
总位移约 0.42 m。

### 6. 僵直清掉的是"它自己想往哪走"，不是"它能不能动"

`stun` 期间 `want = Vector3.ZERO` —— 怪不再朝玩家走、不再游荡。
但**推力永远加**。

如果僵直期间把推力也归零，就会出现"挨打时站着不动"—— 那是最差的反馈：
既没有后退，也没有移动。实测踩过这个坑（退 0.000 m）。

正确的观感是：**一边愣住，一边被推着退**。这才是"被打中"。

### 7. 没有方向就不猜

`damage()` 的 `dir` 参数是水平方向。射线命中时射线方向已知，所以方向是准确的。
但如果 `dir` 是零向量（近战、范围伤害、或者调用方忘了传），
**不猜方向**：只施加僵直，不施加击退。猜一个"从角色中心往外"的方向，
会让玩家觉得这一枪是"凭空被推了一下"，比没反馈还莫名其妙。

### 8. 命中标记：斜线，不是正交短线

准心的四条线是正交的。如果命中标记也画正交短线（在准心四个角上），
它和准心自身的线**方向相同、视觉上分不清**，在 60 帧下根本看不出来。

所以命中标记画成**斜线**，四个角各一条，拼成一个 X。X 是最通用的"打中了"符号，
而且和准心的直角线在形状上就分得开。

持续 **0.18 秒**：短到不挡视线，长到 60 帧下能看见（11 帧）。

## 效果（check.sh 第 19 步实测）

- **会退**：挨一枪往后退的速度峰值 **2.38 m/s**（门槛 ≥ 1.0 m/s）。
- **有牙**：把内容里的 `knockback` 改成 0 再挨一枪，往后退的速度峰值 **0.09 m/s**
  （门槛 ≤ 0.30 m/s）。差 26 倍。
- **会愣**：挨打后 21 帧里，**0 帧**还在往玩家那边凑（门槛 ≤ 2 帧）。
- **命中标记**：打中时准心上的 X 亮着（剩余 0.162 秒）。

**"有牙"对照必须改内容，不能清 meta。** 这是本轮踩的一个坑：
清掉 meta 之后再开枪，`_react` 又会完整写一遍新反应 —— 等于量的是"第二次挨打"，
对照组根本没生效。改内容（`knockback = 0`）才是真正的"关掉这个功能"。

## 代价（明知，故写下来）

- **推力是"瞬时的"，不是持续的物理碰撞。** 一枪 2.5 m/s 的推力没有对应的碰撞体，
  不会把旁边的箱子撞飞。做"子弹推动物体"需要真的物理弹丸，那是另一套东西。
- **僵直期间不会重新寻路**（游荡也停）。如果以后要做"被打晕的怪醒来换个位置"，
  需要在 `locomotion` 里加一段醒来逻辑。
- **命中标记是纯 UI**，不反映伤害大小。打中一只玻璃塔和打中一头牛，标记一样亮。
  要区分得等"弱点"机制。

## 什么情况下应该推翻

- **如果要做"部位伤害"（爆头伤害更高）**：`vitals` 的 `damage()` 要接受部位信息，
  `hit_react` 要能按部位给不同的推力。那时候 `dir` 的语义要从"射线方向"
  变成"射线方向 + 命中点法线"（往里打 vs 擦着打不一样）。
- **如果要做真正的物理弹丸**（子弹是一个刚体，能撞飞东西）：`hit_react` 这一层
  就不该由 `vitals` 驱动，而该由弹丸的碰撞驱动。现在这套是"射线 + 手动推力"，
  换成真弹丸时整条链要重写。
- **如果要给玩家看伤害数字**：那是准心的另一层职责（`on_hit` 已经带了信号，
  加个参数就能传伤害值），但**不要**把数字画在准心上 —— 准心是瞄准用的，
  挂了别的东西会影响手感。数字应该挂在准心旁边而不是准心上。
- **如果多人加入**：击退方向要改成"从射手指向目标的水平向量"，
  而不是"从枪口射线方向"—— 现在的写法在第一人称下两者几乎一致，
  多人时会有偏差。meta 存在本地刚体上，多人时每端各自算，**不会自动同步**，
  那需要走网络层，不是本 ADR 的范围。
