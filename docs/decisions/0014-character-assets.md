# 0014 角色资产：人得真的在走

## 背景

用户 2026-11-20：*"你继续把开放框架完善。完善后，你加点东西，让人物正经"*。

试玩之后最刺眼的不是画面简陋，是**人是滑的**：走路时脚不动，整个人贴着地面平移。
原因不在"缺动画系统"，而在这一层根本没打开 —— 第十一轮的外观开放
（ADR 0012）只做到"换一份静态几何"：`assets/meshes/<id>.gltf` 被烘成一份
`ArrayMesh`，骨架和关键帧在烘焙那一刻就全丢了。

所以这一轮要解决的是一句具体的话：**让玩家身上那个"人"真的在动。**

## 决定

### 1. 角色是独立入口，不能塞进 mesh 覆盖

`ASSETS.character(id)` 返回的是一整棵**带动画的节点树**（骨架 / AnimationPlayer /
贴图 / 76 个片段），而不是 `ArrayMesh`。

如果把角色硬塞进 mesh 覆盖那条路（烘成一份几何），动画会一起被烘掉，
而且**没有任何报错** —— 人还是滑的，探针还是绿的。这是两件事：
一个改的是"世界里的静态形状"，一个改的是"一个会动的实体"。

但它仍然只有一个入口：别的域只调 `ASSETS.character()`，不自己 `new GLTFDocument()`。

### 2. 放仓库根，不放 `game/`

`assets/characters/<id>.glb`，文件名就是 id，没有清单文件。

- 不放 `game/` 是因为那会让 Godot 的导入器在编辑器打开时重新处理一遍 3.5 MB 的 glb，
  生成 `.import` 和 `.godot/` 缓存；而运行时我们用 `GLTFDocument` 直接读磁盘。
  两条路各算一遍，包体里就多一份。
- 放仓库根，它和 mod 目录是一个性质：**投放物**，不是 Godot 工程的一部分。
- 换角色 = 丢一个 glb 进去 + 改 `player.gd` 的 `CHARACTER_ID` 一行。

### 3. 身高只在绑定姿势下量一次

现成资产高矮不一（KayKit 的骑士连头盔羽毛 2.47 米）。不归一化，换个模型就
"人陷进地里"或"浮在半空"。

归一化的坑：**动画一播，手臂抬起、披风摆开都会改变包围盒**。所以
`character()` 只在绑定姿势下量一次 `AABB`、算出 `scale`，把 `scaled_height`
和 `foot` 一起返回。探针断言的是这两个**算出来的**数，不是当前包围盒 ——
后者会随动画漂移，拿它做精确断言就是假红。

当前包围盒只用来做粗检（没陷地、没差一个量级）。

### 4. 可选装备由资产自己声明

KayKit 的角色包把**全部武器和盾牌**都绑在同一个骨架上：一加载就是
左手三面盾、右手两把剑，其中一把两米长的巨剑直接插进地里。

资源没坏 —— 是资源本来就等引擎决定穿哪一件。而"穿哪一件"不该写死在代码里，
换个角色包前缀就变了。所以由资产自己在 `<id>.json` 里说明：

```json
{ "hide_prefix": ["1H_", "2H_", "Badge_", "Rectangle_", "Round_", "Spike_"] }
```

代码只认前缀，不认具体名字。没有这个文件时全部显示（缺省不猜）。

### 5. 卡通着色要有贴图通道

`toon.gdshader` 加了 `albedo_tex` + `use_albedo_tex`，默认关。

现成资产靠一张渐变图集上色，换成纯色会丢掉所有细节；但程序化几何没有 UV 语义，
强行采样只会是噪点。所以做成开关，由资产加载器在拿到贴图时打开。
用**乘法**而不是替换，`base_color` 仍然能给它染色（受击泛红之类）。

材质按（贴图, 颜色）共用一份：一个角色 8 个可见 surface 只产生 1 份材质，
符合第 13 步那条"材质数跟着配色走，不跟着物体数走"。

### 6. 拿不到资产时必须还能跑

资产目录是可以整个删掉的。删掉之后游戏必须还能玩，哪怕人重新变成一个会滑的方块
（`character_rig.gd::_build_fallback`）。

一个装不上就满屏空白的加载器，比没有加载器更糟。

### 7. 验收守的是"真的在动"

`check.sh` 第 14 步（`game/probes/character.gd`）六条断言：
结构 / 片段 / 骨架 / 身高 / 落地 / 材质 / 回退 / 走路 / **动** / 状态机。

最后一条是重点：它**直接采样骨骼姿势、跨帧比较**，而不是看
`AnimationPlayer.current_animation` 的名字。

负向验证过：把 `_ap.play()` 掐掉，"走路"那条**仍然显示 true**（状态名改了），
只有"动"这条从 36/41 掉到 0/41 并且判红。没有这一条，整个探针可以在
"人是滑的"情况下全绿。

## 代价

- 仓库多了 3.5 MB（`knight.glb`）。只放了一个角色，另外三个留在原地 ——
  换角色本来就是拷一个文件的事。
- 角色资产只在**编辑器二进制**上验证过。导出包里 `GLTFDocument` 是否可用，
  仍未验证（ADR 0012 的推翻条件同样适用于这里）。
- 动画只有"按速度挑片段 + 0.18 秒交叉淡入"。没有混合树、没有根运动重定向、
  没有 IK。76 个片段里目前只用了 6 个。
- 描边在骨骼网格上是靠 `vertex()` 沿法线外扩——**在蒙皮之前**。视觉上目前正常，
  但极端姿势（大幅挥砍）可能出现描边穿帮，未验证。

## 什么情况下应该推翻

1. **要把同一套角色用到几十个实例上**：现在每次 `character()` 都重新解析
   3.5 MB 的 glb，造一棵新树。多个实体共用同一角色时应该改成
   "解析一次 GLTFState、实例化多次"，否则加载时间线性增长。
2. **要真正的动画状态机**（连招、上下半身分层、根运动）：这一层的
   `update_locomotion` 是一张速度表，撑不起这些。到时候应该换成
   `AnimationTree`，而不是在这张表上继续加分支。
3. **导出包里 `GLTFDocument.append_from_file()` 不可用**：那就得改走
   `res://` 导入管线，`assets/characters/` 要挪进 `game/`，本节第 2 条作废。
4. **描边在骨骼上出现穿帮**：换成正向渲染的第二个 pass 或屏幕空间描边，
   代价是 Compatibility 下没有免费深度纹理，会很贵。
