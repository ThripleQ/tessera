# 0010 背包与准星

## 背景（一句话）

右键"拆掉"把东西从世界里删掉，删掉不可逆 —— 玩家于是不敢动自己刚摆好的东西；
而"瞄哪儿放哪儿"在第三人称下也没法用屏幕中心实现。

## 决定（一句话）

右键改成**收进背包**（记事本式的 id + 件数，不记位置），菜单把背包和凭空生成
合成同一份清单；准星画在**手那条射线打到的地方**，不画在屏幕中心。

## 为什么"收"而不是"删"

预算上限 96 件，在"收"之前没有任何办法把它还回去 —— 玩家放满之后沙盒就死了。
所以第一版的右键是"拆"，功能上解决了这个问题，但从另一个方向把它锁死了：
**删掉不可逆，玩家就不敢动手。** 摆一件东西是想清楚才摆的，删掉是净损失。

收进背包之后，东西没消失，只是回到"我有什么"的账上。"能放能收"才算成立。

## 为什么背包只记 id 和件数

记位置的话，背包里就得维护一个"静止的世界"：东西在地板上要算支撑、叠起来的要算
相对位置、读档时要重建这些关系。那是独立的物理模拟，而且和
"存档只存玩家的动作"这条分界正面冲突 —— 玩家的动作是"我把这个放在这儿"，
不是"这个物体曾经在这儿"。

所以「放出来」是**重新造一件**，不是把某个具体的物体搬回去。丢掉的是
"这件箱子曾经被我推过三次"这种叙事，换来的是背包可以在任何地方、任何时刻还原。

## 为什么准星是 3D 的环而不是屏幕十字

第三人称相机在身后 3.8 米。屏幕中心和手的射线指向的不是同一个点 ——
屏幕中心准星会让玩家"对着准星按，拿走的是别处的东西"，而且没有任何提示。

3D 环画在射线的落点上，于是它和 `aim_node()` 共用同一条射线：
**准星是射线的显示，不是射线的定义。** 它必须是同一个东西，否则某天两条射线
会在起点、距离、屏蔽列表上分叉，表现成"有个位置明明能抓却收不到"。

## 被否掉的选项，以及为什么

- **两栏菜单（生成 / 背包）**：玩家每次都要想"我刚捡的那个在哪一栏"。
  合成一份清单之后，"有库存就先扣库存"是内部实现，玩家不用知道。
- **背包有容量惩罚（重量、格子）**：现在没有"必须有代价"的理由，
  加限制只是在验证阶段给自己造平衡问题。128 件的上限只是为了兜底。
- **背包里能存"某一件具体的物体"**：见上，那等于在背包里模拟一个静止的世界。
- **准星用屏幕十字 + 世界落点双显**：两个指示器会有两个答案，
  而"到底按哪儿"只应该有一个答案。

## 什么情况下应该推翻这个决定

- 如果做**拾取并携带**（手上拿着、可以放下到任意位置），那时"具体的物体"
  会重新变得有意义，背包可能需要记"这一件的朝向"。
- 如果 mod 需要往玩家背包里塞东西，说明背包成了通用容器而不是玩家的私有状态，
  那时要重新划"谁能写存档"这条线（现在明确不让 mod 写）。
- 如果哪天准星要显示"放下之后的占地范围"（摆建筑时有用），
  3D 环会不够用，需要换成世界空间的预览网格 —— 但落点仍然只能有一个来源。

## 修订（2026-11-14）：堆叠上限与价值

原决定"只记 id 和件数"不变。补两条，都是**内容说了算**：

- `pickup.stack` = 同 id 在背包里的堆叠上限。`add()` / `from_save()` 强制，
  满叠时 `collect()` **先拒绝再保留世界里的那一件**。没有 pickup 的东西不限叠。
- `pickup.value` = 价值，`total_value()` 合计进菜单状态栏。

背包因此认识 `pack`，但**只问两个数**（能叠多少、值多少），不认识节点、
位置、物理 —— "背包里没有一个静止的世界"这条边界没有动。
手改存档把 25 个骨符塞进 20 一叠也会被压回去：数据规则不因为来源是文件就让步。
