# ADR 0019：子弹从枪口出去，枪管对着落点；两个视角各有一把枪

- 日期：2026-11-21
- 状态：已落地（第二十二轮）
- 相关：ADR 0016（FPS 训练场）、ADR 0018（受击反馈）

## 背景

第二十一轮把枪换成了带手臂和三段动画的 AKM，看起来像枪了。但玩起来有一处
说不通的地方：

- **子弹从眼睛出去。** 射线起点是相机，曳光画在屏幕中心那条线上。
  低头看枪管，枪管指着左边；子弹却从画面正中飞出去。玩家靠近墙、贴近箱子
  的时候尤其明显：明明枪口还露在外面，子弹却从"脸"的位置出发。
- **第一人称和第三人称看到的不是同一件事。** 切到第三人称，枪直接消失 ——
  相机上的视图模型被藏起来了，而世界里没有第二把。玩家看到一个空手站着的法师。

用户的说法是"能不能是是什么就是什么，和现实世界逻辑一样"。
这两条都不是"画得不好看"，是**画面在说谎**：同一颗子弹，眼睛看到两条弹道；
同一把枪，换一只眼睛看就没了。这种不一致会让人怀疑整个世界的规则。

## 决定

### 1. 准心只回答"打哪儿"，枪口回答"从哪儿打"

```
起点 = 枪口世界位置（视图模型上量出来的那个点）
终点 = 屏幕中心射线的落点
方向 = (终点 - 起点).normalized()
```

两件事分开之后，每个都能单独验证：

- 起点对不对：`last_from.distance_to(前置帧的 muzzle_world()) < 0.01`；
- 打没打准：枪管朝向与 `last_to - last_from` 点积 `> 0.999`。

**枪口位置不是猜的。** 模型在相机下有一个已知的摆放（`REST_POS` 等），
`MUZZLE_VIEW_POS = (0.181, -0.082, -0.52)` 是从截图上一像素一像素量出来的
枪管末端，再换算回模型局部坐标：

```gdscript
_muzzle_local = _model.transform.affine_inverse() * MUZZLE_VIEW_POS
muzzle_world()  = _model.global_transform * _muzzle_local
```

模型怎么动（呼吸、走路晃、甩枪、开火后坐），枪口就跟着动到哪。
换美术资源时这个数要重量 —— 它和模型是绑定的，不是引擎常量。

### 2. 散布也要看得见

散布是"这一枪瞄偏了多少"，所以：

1. 先从枪口朝准心落点求出方向；
2. 再绕**相机轴**抖一个角度（抖的是瞄准偏差，不是枪口位置）；
3. 射出去，拿到真实落点；
4. **把枪管转过去对准那个真实落点**。

第 4 步是关键。如果只抖子弹不抖枪，玩家看到的是"枪口纹丝不动，子弹歪了" ——
正是本轮要修的那种分裂。枪管跟着抖，玩家才读得懂"这一枪本来就有点偏"。

顺序也有讲究：`tick()` 里**先摆枪口、后开火**。反过来的话，开火时 `_fire()`
刚把枪管对准实际落点，紧接着同一帧又被"对准准心"覆盖回去，等于没做。

### 3. 转枪管绕枪口转，不是绕模型原点

枪管的轴是模型的 `+X`。要把 `+X` 转到目标方向，最自然的写法是
`Quaternion(barrel, want)`，但那样旋转中心是模型原点 —— 瞄准时整把枪会平移，
枪口在画面里跟着飘。

正确做法是**绕枪口这个点转**：

```gdscript
var nb := Basis(Quaternion(barrel, want)) * b
xf = Transform3D(nb, muzzle - nb * _muzzle_local)
```

枪口不动，枪身绕着它转。准心在画面中心不动，枪管末端也就是那个位置 ——
画面上就是"枪口钉在那儿，枪身微微转"。

### 4. 曳光：一条 0.06 秒的光束，从枪口到落点

子弹仍是瞬时射线（不是物理弹丸），但**看得见**：从 `last_from` 到 `last_to`
拉一根加法混合、不受光的细长盒子，0.06 秒淡出。它存在的唯一理由是让
"从枪口出去"这件事在画面上有证据 —— 没有它，起点改对了玩家也看不出来。

### 5. 两个视角，两把枪，同一份资源

| | 第一人称 | 第三人称 |
|---|---|---|
| 模型放哪 | 相机下（相机空间） | 世界里（法师右手骨上） |
| 缩放 | 0.026（约 12 cm 的视图模型） | 0.10（约 45 cm 的真枪） |
| 谁看得见 | 只有玩家 | 只有别人 / 玩家切过去时 |
| 参与开火 | 是，枪口就是弹道起点 | 否，纯视觉 |

两边都加载同一个 `assets/weapons/akm_fps.glb`，各藏各不需要的部分：
视图模型留着手臂，世界里的那把藏掉 `ArmModel`（法师有自己的手）。
`set_shown()` 同时开关两者 —— 永远恰好有一把可见。

**为什么不做成"一把枪换个父节点"**：两边的缩放差四倍、需要的动画状态不同
（视图模型有甩动 / 后坐位移 / 换弹变速），共用一个实例就要在切换时重置一堆
状态，而且切换那一帧必然出错。两个实例各管各的，代价只是多一份内存。

### 6. 世界里的枪跟着右手骨走

第三人称的枪挂在**右手骨的位置**上，每帧读骨头世界坐标，朝向由身体前向构造：

```gdscript
var at := _hand.global_position + up * HOLD_LIFT - fwd * HOLD_FWD
var b  := Basis(fwd, Vector3.UP, fwd.cross(Vector3.UP))
```

不把骨头当父节点，因为骨头自己的坐标轴长短不一，把枪塞进去会得到一个
"看起来随机"的朝向。骨头只当**位置探针**，朝向自己算。

两处微调是看着截图量的，都是为了"从背后看得见"：

- 枪口下压 20°：法师的帽子有一米宽，水平端着时整把枪被帽檐和袍子挡住；
- 枪口右偏 17°：身体是圆的，沿正中线指出去从背后只剩一个枪托截面。

代价是"这不是模型作者设计的持枪姿势"，是取景的妥协 —— 写在这里，免得
下一个人以为是动画调好的。

### 7. 相机过肩，否则第三人称看不见自己手里的东西

默认第三人称相机在正后方。帽子 + 袍子 + 后脑勺占满画面中心，右手边的枪
永远在遮挡后面。把弹簧臂的根部右移 0.55 m、抬高 0.10 m（过肩视角），
枪才进入取景。

**偏移必须写在弹簧臂上，不能写在相机上**：`SpringArm3D` 每帧把直接子节点
摆回 `(0, 0, spring_length)`，写在 `_camera.position` 上的 x 会被无条件覆盖，
症状是"改了数，画面一点没变"。

## 效果（check.sh 第 17 步实测）

```
GUN 枪口即弹道：起点在枪口 是（偏 0.000 m）/ 枪管对弹道 是（点积 1.0000）
                / 曳光 是 / 飞出去 是
GUN 两个视角都有枪：第一人称（相机上的枪 是 / 世界的枪 不是）
                  / 第三人称（相机上的枪 不是 / 世界的枪 是）都 是
```

- 起点偏差 **0.000 m**：曳光第一帧就在枪管末端，而不是屏幕中心。
- 枪管与弹道点积 **1.0000**：打出去的线和看到的枪管是同一条。
- 切换视角后**恰好一把**可见，且世界里的那把真的加载出来了
  （`model_ok()`，不是"节点在但模型失败"）。

## 代价（明知，故写下来）

- **子弹仍是射线，不是弹丸。** 没有飞行时间，打移动目标不用提前量。
  曳光只是"让起点可见"，不代表子弹真的在路上。要真弹丸见推翻条件。
- **两把枪 = 两份动画状态。** 切视角时世界里的那把不会继承视图模型的
  后坐 / 甩动，它只是继续播 Idle。对第三人称来说这没问题（那里不开火），
  但以后如果第三人称也能开枪，两边的动画要先对齐。
- **枪口位置是标定的数。** 换模型、改 `GUN_SCALE`、改握枪姿势，都要重新量
  `MUZZLE_VIEW_POS`；量错不会报错，只会"子弹从枪管旁边飞出去"。
- **世界里的枪持枪角度是为了露出来，不是为了正确。** 下压 20° + 右偏 17°
  在近距离特写下能看出"枪口没对着前方"。远处（正常游玩距离）读不出来。
- **第三人称开枪不存在。** 左键在第三人称是抓取，切过去时扳机会被松开。
  所以世界里的那把枪不需要弹道，也不需要准心。

## 什么情况下应该推翻

- **如果要做真正的弹丸**（有飞行时间、会被墙挡住、能打飞东西）：
  起点仍然用 `muzzle_world()`，但"曳光"要换成弹丸本体，落点由物理碰撞给，
  而不是射线。`_fire()` 里的 `_cast` 整段重写，这一层不用动。
- **如果第三人称也要能开枪**：相机过肩的偏移就是准心偏移（准心在画面中心，
  而射线从肩膀右边发出），要么把准心挪过去，要么让第三人称自动回正。
  另外世界里的枪要接后坐与开火动画，且它的枪口要成为弹道起点。
- **如果换枪 / 支持多把武器**：`MUZZLE_VIEW_POS` 这种每把枪一份的标定值
  应该进内容（`wieldable` 组件的 `muzzle` 字段），而不是常量。
  现在只有一把枪，先不引入这个复杂度。
- **如果做肩射 / 腰射的姿势区分**：`HOLD_PITCH` / `HOLD_YAW` 会从常量
  变成状态机的一部分，视图模型和世界模型要共用这套姿态定义。
- **如果做多人**：别人看到的枪要在网络上同步朝向与动画状态，现在它是
  每端自己按本地身体朝向算的，多人时会各算各的。
