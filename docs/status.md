## 已知问题 / 必须记住的坑

- **无 GPU 直通**（无 `/dev/dri`），只有 llvmpipe。帧时没有参考价值，画面可信。
  **不要用这台机器的帧率做任何性能结论。**
- **卡通着色的亮度是标定出来的，不是算出来的**。Compatibility 的 `LIGHT_COLOR` 与
  Forward+ 不同量级，`toon.gdshader` 里的 `light_gain` 是实测值。换渲染器必须重新标定。
- **自检只走到 Plan 层，不实例化玩家**。`player.gd` / `grab.gd` / `store.gd` 的运行时
  错误 `check.sh` 抓不到。所以有两道额外防线：`game/probes/save_roundtrip.gd`（存档）
  和"改完真的跑一次窗口"（其余）。
- **抓取的射线必须从角色胸口发出**，不能从相机。第三人称相机在身后 3.8 米，
  从相机发一条 3 米射线，走到头刚好停在角色后脑勺——第一版就是这么错的，
  表现为"永远抓不到东西"，而且没有任何报错。
- **拉的是质心不是原点**。内容的原点在底面（所有东西都站在自己的原点上），
  把原点拉到胸口的结果是箱子悬在胸口上方浮着。
- **撞击速度必须缓存上一物理帧**。`body_entered` 到达时接触已经解算完，
  此刻 `linear_velocity` 往往已经归零，用它算出来的撞击永远是 0。
- **动态物体不合批**。想加大量可动物体之前，先想清楚提交次数。
- **`pass` 是 GDScript 关键字**，不能当变量名（`var pass := ...` 会 Parse Error）。
  探针第一版撞上了：错误只出现在运行 `--script` 时，`check.sh` 的第 5 步看不到它。
- **`run.sh` 的参数白名单**：`--trust=*` / `--selftest` / `--fresh` 要放进 `--` 之后，
  其余给引擎。新加一个游戏参数必须同时改这里，否则它会被 Godot 当成自己的参数吞掉。
- **只有 4 / 13 个组件被引擎读过**（model / collider / spawner / room）。
  `move` / `ai` / `health` 仍是死数据。
- **导出包未验证**：运行时 GDScript 编译只在编辑器二进制上验证过。P6 前必须重测。
- **mod 无沙箱**：`OS.execute` 实测可执行。授权是唯一防线（ADR 0003/0008）。
- **mod 产物不进版本库**，`clone` 后要先跑 `./run.sh` 或 `./check.sh` 编译一遍。
- **房间之间没有门**，走道只是空地；世界是一条直线排列的房间（ADR 0004）。
- **存档不含 mod 状态**。mod 卸载后存档里它的东西会"找不到内容"，读档时会列出来。

## 待定（需要人拍板）

- 仓库名 `tessera` 是临时的，随时可改
- **要不要贴图资产管线**：现在全靠程序化几何 + 顶点色。要做到"像原神的角色"必须上贴图
  （脸、眼睛、服装），那是 P3 的事，但决定得早——它会牵动外观开放的覆盖规则
- **mod 授权 UI 什么时候做**：现在只有 `--trust` 命令行。P5 之前必须有 UI，
  否则"玩家显式授权"对普通玩家等于不存在
- **存档要不要自动存得更勤**（现在只有关窗口 + F5）。频繁自动存档会让"我明明没存"
  这件事失去意义，得先想清楚玩家预期
- 是否要在 P5 之后引入 Lua 作为 mod 脚本语言（ADR 0003 已否）
