## 已知问题 / 必须记住的坑

- **无 GPU 直通**（无 `/dev/dri`），只有 llvmpipe。帧时没有参考价值，画面可信。
  **不要用这台机器的帧率做任何性能结论。**
- **卡通着色的亮度是标定出来的，不是算出来的**。Compatibility 的 `LIGHT_COLOR` 与
  Forward+ 不同量级，`toon.gdshader` 里的 `light_gain` 是实测值。换渲染器必须重新标定。
- **自检只走到 Plan 层，不实例化玩家**。`player.gd` / `hands.gd` / `store.gd` /
  `ui/spawn_menu.gd` 的运行时错误 `check.sh` 第 5 步抓不到。所以有三道额外防线：
  `probes/save_roundtrip.gd`、`probes/spawn_menu.gd`、以及"改完真的跑一次窗口"。
- **`:=` 推不出类型时会 Parse Error，而编译期完全没提示**。`pack` 是 untyped 的，
  `var x := pack.some_bool()` 会炸在**加载这个文件的那一刻**（游戏或探针），
  而不是 `check.sh` 第 5 步。写 `var x: bool = ...`。
- **抓取的射线必须从角色胸口发出**，不能从相机。第三人称相机在身后 3.8 米，
  从相机发一条 3 米射线，走到头刚好停在角色后脑勺。
- **拉的是质心不是原点**。内容的原点在底面，把原点拉到胸口的结果是箱子浮在胸口。
- **撞击速度必须缓存上一物理帧**。`body_entered` 到达时接触已经解算完。
- **动态物体不合批**。想加大量可动物体之前，先想清楚提交次数。
- **静态物不是免费的**。它不参与模拟，但碰撞体永久占用物理查询，所以也计入
  `MAX_SPAWNED` 预算。
- **预算按节点身份记账，不是一个计数器**（`api._made`：instance_id → handle）。
  计数器记不住"哪几件是我造的"，于是拆掉的东西照样占额度，读一次档额度还会清零。
  读档恢复的东西必须 `api.adopt()` 认领回来，否则读档就是无限刷物的后门。
- **房间自带的障碍和玩家摆的柱子长得一模一样**，区别只在归属：前者在 chunk 里，
  后者在 `world.props` 里。`world.remove_thing` 只认后两个列表 —— 这就是
  "房间拆不掉"的全部实现。别把这条守卫改成"按 collider 是不是 static 判断"。
- **类型化数组的 `find` 会报错，但"刚好"返回 -1**。`bodies` 是 `Array[RigidBody3D]`，
  拿 `StaticBody3D` 去 `find` 会打一条引擎 ERROR 再返回 -1 —— 恰好落到正确分支。
  断言全绿、功能正确、日志每右键一次墙就脏一行。**先按类型分岔再 find**。
  这一类"刚好对"的实现最难发现，见下一条。
- **验收曾经只 grep 业务标记，于是引擎报错完全不可见**。现在 `no_engine_errors()`
  把 `^ERROR` 一律算失败（第 5/6/7 步都过一遍）。摘钩验证过一次：把上面那个
  `find` 的错误用法放回去，`MENU RESULT OK` 仍然打印，但验收红 —— 这就是它存在的理由。
- **`pass` 是 GDScript 关键字**，不能当变量名（`var pass := ...` 会 Parse Error）。
- **`run.sh` 的参数白名单**：`--trust=*` / `--selftest` / `--fresh` 要放进 `--` 之后。
  新加一个游戏参数必须同时改这里。
- **9 / 13 个组件被引擎读过**（model / collider / spawner / room / pickup /
  move / ai / health / loot）。剩下 4 个是死数据：`light` / `interaction` /
  `wieldable` / `transform`。骨行者不再是雕像 —— 会走、会死、会掉，
  但"开关门、举火把、拿武器"还是写不出来的。
- **mod 的编译产物会过期，而且过期得很隐蔽**：`hard_mode` 的旧 `content.pack.json`
  里 `collider.dynamic` 还是 false，编译基础内容时新值刚写进去，**mod 合并又按 id
  覆盖回旧值** —— 怪变回雕像，全程没有任何报错。改契约/内容后必须重编 mod
  （`check.sh` 第 2 步就是干这个的，本地只跑单个探针不算数）。
- **视锥判据的正负号写反不报错**：Godot 的视锥平面法线朝外，点在视野内时
  `distance_to` 是**负**。取"最可能在外的顶点"还是"最可能在内的顶点"也容易搞反。
  写错的症状是"画 2 剔 17"或全画 —— 一切正常，只是该画的没了。
  所以剔除探针里有一条**与 Godot `is_position_in_frustum` 逐件对拍**，改剔除必看它。
- **绝对计数的断言会被内容变化打破**：存档探针曾写死 `bodies.size() == 14`，
  怪变刚体后红 —— 红的是断言不是功能。数量断言用"存档那一刻"的相对基准。
- **一个房间只能填一种东西**：`spawner` 是单组件，一个房间实体只能有一个。
  "墓厅地上散着骨符 + 6 只骨行者"这种内容今天写不出来。要修就改 `spawner`
  支持分组（`groups` 列表），趁内容还只有 3 个房间的时候改最便宜。
- **`set_pose` 的方向要下一帧才生效**：它改的是 arm 的旋转，相机的全局变换
  要等场景树下一帧才传播。**调完视角就同帧算落点，算的还是旧朝向的** ——
  东西放在"我以为在的地方"的旁边，射线却指向真正的地方。
  探针踩过：骨符放在落点上，收却收不到。规则：调视角一帧，用方向下一帧。
- **放和收之间隔着几帧 = 物理噪声**。刚体被传送后会被推开、滚走，
  隔 6 帧射线就可能落空，而那不是功能的问题。探针里放和收**同一帧**完成。
- **本地过、CI 红，几乎总是"本地有残留状态"**。踩过一次：第 1 步的编译器自测往
  `build/` 写日志，而 `build/` 是「编译内容」那一步才创建的，干净 clone 上必然失败。
  验证方式是 `rm -rf build && ./check.sh`。
- **探针截图只在有显示的本机产出**（`game/*.png` 已 gitignore）。CI 是无头的，
  拿不到视口纹理；"因为截不到图所以整条失败"会让这条检查被人删掉。
- **导出包未验证**：运行时 GDScript 编译只在编辑器二进制上验证过。P6 前必须重测。
- **mod 无沙箱**：`OS.execute` 实测可执行。授权是唯一防线（ADR 0003/0008）。
- **mod 产物不进版本库**，`clone` 后要先跑 `./run.sh` 或 `./check.sh` 编一遍。
- **房间之间没有门**，走道只是空地；世界是一条直线排列的房间（ADR 0004）。
- **存档不含 mod 状态**。mod 卸载后存档里它的东西会"找不到内容"，读档时会列出来。
