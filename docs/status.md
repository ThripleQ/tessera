## 已知问题 / 必须记住的坑

- **Godot 的 `play()` 不重置播放位置**：切到新片段时它从**旧位置**接着播。
  两条片段长度不同时，接着播就是从一个错乱的相位开始 → 脚跳。
  本来以为 `play()` 会从头播，试出来才发现不是。
- **带淡化的 `play()` 会让 `seek()` 失效**：位置跟着走，**骨架纹丝不动**。
  所以"交叉淡化 + 相位对齐"在 Godot 上互斥，只能二选一 ——
  而实测淡化期间脚会以 0.8 m/s 往身体中心收（真滑），所以选硬切（ADR 0017）。
- **`play()` 之后骨架不会立刻更新**：`play()` 只设位置，姿势要 `seek()` 或
  `advance()` 才刷新。探针里漏了这一步，"有牙"对照会量成 0.000（假的通过）。
- **`foot_bones()` 返回 12 根骨**（含 control-* / IK-* / toes），不是两只脚。
  按"哪根最低"挑支撑脚会每帧在它们之间跳，一次都统计不上；
  而且**摆动脚经过最低点时也是贴地的**（实测贴地却速率 2.7 m/s），
  挑错脚会把摆动当成滑步（起步时量到 1.7 m/s 的假滑）。
  逐帧判支撑脚不可靠 —— 改用"倍率有没有被夹住"这个构造量
  （第 15 步已用两套独立实现验过"倍率对齐 ⇒ 脚钉住"）。
- **探针里逐帧推进动画要用 `advance()`，不能用 `seek()`**：`seek()` 会打断
  交叉淡化，把骨架冻在旧姿势，量到的"脚在动"全是假的。
  同时要把播放器的自动推进接管掉：
  `_ap.callback_mode_process = AnimationMixer.ANIMATION_CALLBACK_MODE_PROCESS_MANUAL`，
  否则引擎自己也会 advance 一次，每帧走的时间不是探针给的那一点。
- **类型化数组 `Array[Vector3]` 给索引赋值会报 "Invalid assignment"**：
  换成无类型 `Array` 就行；代价是元素变成 Variant，`:=` 推不出类型，
  得显式写 `var d: Vector3 = ...`。
- **默认第一人称会让所有第三人称探针悄悄变红**（第十八轮）。第 8 步验的是
  抓 / 放 / 准星环 / 收进背包，而第一人称左键是扳机、屏中是另一个准心、
  落点圈故意藏着。`spawn_menu.gd` 探针必须在 `_initialize` 里显式
  `_main._player.toggle_view()` 切回第三人称 —— 红的是断言不是功能。
  凡是"假设了某个视角"的探针，都要**显式声明视角**，不要吃默认值。
- **Quaternius 的枪模型也带 100 倍缩放**（和角色同一个坑）。`rifle.glb` 原始
  包围盒 2.9 m，要再乘 0.18 才是 0.52 m 的枪。枪口火焰是相机空间的一个 quad，
  位置得按缩放后的枪管末端量，不能按模型原点 —— 差一点就飘在画面外。
- **`player.gd` 第三次撞上 400 行**（403 行，第十八轮）。这次是视角 + 枪 +
  骨架三件事挤进来。拆成 `view.gd`（视角 / 后坐）、`skin.gd`（骨架 / 步速）、
  `motion.gd`（求方向 / 推箱子）、`gun*.gd` 后回到 363 行。
  **这条线每次都在"一个文件正要开始做两件事"时响**，别去放宽它。
- **步态扫描工具漏乘绑定矩阵会静默输出空表**（已修，587cf6f）。对 Quaternius
  这种骨架挂在 100 倍缩放节点下的模型，测出来的数小到被筛掉，症状是
  "这个角色没有移动动画" —— 而它其实有。修完才量出 man 走路 2 毫米这个真数。
- **"每次打开重置"不是把存档删掉**：默认不读档，`--resume` 才读。
  沙盒那边（玩家摆的静态物 / 背包）仍然依赖存档，删了会连带拆掉第 7 步。
- **后坐不能写进鼠标的 `_pitch`**。两者分开存，回位之后玩家瞄准的点还在原处；
  写在一起连发几枪准星会永久偏，看起来像鼠标坏了。回位只加在相机上，
  不加在身体上，否则走路方向跟着枪口漂。
- **`MeshInstance3D` 没有 `material` 这个属性**。要按优先级取三层：
  `material_override` → `get_surface_override_material(i)` → `mesh.surface_get_material(i)`。
  探针里原来写的是 `mi.material_override if ... else mi.material`，**一直没炸**，
  因为全世界都有 `material_override`，三元短路掉了右半边；角色用 surface 级材质的那一刻才踩到。
  这一类"刚好对"的写法，只有在一条**新的代码路径**经过它时才会露出来。
- **角色身高必须在绑定姿势下量**。动画一播，手臂抬起、披风摆开都会改变包围盒 ——
  那时量到的是"这个人这一刻多高"，不是"这个人多高"。归一化只在 `character()`
  里做一次并把结果缓存进 `_char_meta`；探针断言 `scaled_height` / `foot`，
  当前包围盒只做"没陷地"的粗检。拿当前包围盒做精确断言会假红。
- **骨架可能挂在缩放节点下，长度可能藏在绑定矩阵里**（2026-11-20，加 Quaternius 的
  模型才暴露）。`man.glb` 的骨架节点是 **100 倍缩放**，骨骼自身的位移只有 0.006 ——
  真长在 `inverseBindMatrices` 里。只读骨骼量出来的步速会小一个数量级，
  而它**看起来是个正常的数**（0.006 m/s），比直接失败难查得多。
  现在 `stride.bone_at` 会乘绑定矩阵，把坐标换算到**网格空间**；
  探针那一侧也必须同样乘，否则一边乘一边不乘，会假红或假绿。
  副产物：骑士的真实步速上浮三分之一（0.74 → 0.99 m/s），因为以前少乘了这层比例。
- **反向外扩的描边遇到法线不规整的网格会炸成一屏黑碎片**。不是模型坏了 ——
  模型本身画得好好的，只是 `VERTEX += NORMAL * width` 对这套法线不成立。
  `<id>.json` 里 `"outline": false` 关掉。Quaternius 那一家的模型全都会踩到。
- **"长得对"不等于"动画能用"**。`man.glb` 的走路一个循环脚只走 **2 毫米**，
  正常人要 70 cm —— 这是整套 in-place 动画，调播放倍率只会原地踏得更快。
  而"好看"这件事在静态截图里完全看不出来（这次就是静态看着挺好，一量就废了）。
  所以挑现成角色要看两件事：网格干不干净、**动作里脚走多远**。
  ⚠️ **Quaternius 全家桶都是 in-place** —— 别指望在它家里换个包就解决了。
- **帽子不能算进身高**（2026-11-20 加第二个角色才暴露）。法师的尖顶帽比人头高
  0.8 m，把帽子算进包围盒等于把人缩了 44%：法师走 0.39 m/s，骑士 0.79。
  而"脚不打滑"那一条**照样是绿的**，因为速度和缩放是同一个比例 ——
  **自洽地错了**，这是最难被断言抓到的一类。现在挂在 `head`（BoneAttachment3D）
  之下的网格不参与身高；代价是探针的包围盒上限从 1.25 倍放宽到 1.45 倍
  （帽子本来就该超出去，不放宽会误判正常角色为"尺寸错了"）。
- **现成角色包会把全部可选装备都绑在骨架上**。KayKit 的骑士一加载就是五把武器四张盾，
  其中一把两米长的巨剑直接插进地里。这不是资源坏了，是资源等引擎决定穿哪一件。
- **"每个角色写一份装备前缀名单"是条走不通的路**。第一版用 `<id>.json` 的
  `hide_prefix` 点名（`1H_` / `2H_` / `Round_`…），加第二个角色立刻写不动：
  法师叫 `1H_Wand` / `Spellbook`，骷髅叫 `Knife` / `Throwable`，每家都不一样。
  改成按**位置**判：`handslot` 之下一律摘 —— 四个冒险者模型、四个骷髅模型全都如此，
  这是 Mixamo 绑定的惯例。**名字是各家的，位置是共有的。**
- **只验玩家身上那个角色，等于没验角色通道**。加 mage 时它身高错了、手上举着法杖，
  而第 14 步（当时只测玩家身上的 knight）全绿。现在遍历 `assets/characters/`
  里的每一个 id，各自从零建一棵树断言 —— 新角色进来就有验收，不用先想起去改探针。
- **`character(id)` 不能缓存加载结果**。节点只能有一个父节点 —— 复用会让第二个使用者
  把第一个人从世界里拽走，而症状是"加了个 NPC 之后玩家不见了"，**没有任何报错**。
  第 16 步专门守它（"同一份资产要两次 → 两棵树、两个播放器"）。
- **状态名不等于片段名**。骷髅包有四档步态，而状态只有 walk / run 两个 ——
  按状态切片段的话，中间那几档永远播不出来，冲刺时播的还是慢跑那条、靠把倍率拉满
  硬撑，于是脚重新开始滑；而状态名 / 片段名 / 倍率**三样看起来都对**。
  切片段要按片段名比较，状态名只是给人看的标签。
- **`rig.swap()` 必须先 `remove_child` 再 `queue_free`**。`queue_free` 是延迟的，
  只调它的话这一帧剩下的时间里旧树仍挂在父节点上，紧接着的 `find_child` 会摸到旧骨架 ——
  两套动画同时驱动两个骨架，画面上只看得见一个，另一个在后台白烧帧时间。
- **世界里有别人之后，探针不能按 `CharacterBody3D` 找玩家**。
  `for c in main.get_children(): if c is CharacterBody3D` 会取到第一个，而那可能是 NPC；
  症状只是几条数对不上，看起来像"手感变了"。一律按名字取 `get_node_or_null("player")`。
- **NPC 的动画要跟实际位移，不能跟 `velocity`**。`velocity` 是意图，撞上箱子的那一帧
  还没被解算；按它驱动，卡在墙角的骷髅会原地踏步到天荒地老。
- **`assets.gd` 一度涨到 506 行，被第 3 步拦下**。它确实在做两件事（静态几何 / 带动画的树），
  拆成 `assets.gd` + `character_assets.gd`。角色层的问题走 `ASSETS.note_problem()`
  汇总到同一本账，否则"角色加载失败"会从自检里静默消失。
- **纯物理量分不开"走路"和"挥刀"**（2026-11-20 实测）。一开始想靠"脚有没有匀速后撤"
  自动挑步态，结果 76 条动画里筛出 **11 档**，最小的一档 0.09 m/s —— 攻击、闪避、
  死亡、爬起来的片段全混进来了，它们的脚也在原地蹭。加了两项判别量（支撑占比 /
  直线拟合残差）再看数据：闪避 `Dodge_Backward` 残差 0.053、支撑占比 0.42，
  比 `Walking_A`（0.066 / 0.48）**还规整**。结论：这是识别问题不是数学问题，
  所以改成**资产点名 + 代码实测**，别再往下堆启发式。
- **`value_track_interpolate()` 只对变体轨道有效**。喂给它一条位置 / 旋转轨道会
  **安静地返回 null**，不报错、不生效，症状是"测出来的速度永远是 0"。
  3D 变换轨道要用 `position_track_interpolate()` / `rotation_track_interpolate()`。
- **`seek()` / `advance()` 在 `_initialize` 阶段是空操作**。想在加载流程里同步驱动骨架
  量脚步，量到的永远是绑定姿势。所以 `stride.gd` 走"直接求值动画曲线"这条路；
  等节点 ready 之后（探针里第 6 帧）`seek()` 才真的能驱动骨架。
- **落地锁会把探针的每一次采样都变成 `Jump_Land`**。`_on_floor` 初始是 false，
  第一次 `update_locomotion` 会被判成"刚落地"并锁 0.3 秒 —— 之后的采样全在测落地动作，
  而**状态名看起来完全正常**。探针每次驱动前必须清 `_lock` / `_on_floor`。
- **`character_assets.gd` 涨到 439 行又被第 3 步拦下**（这是第二次）。
  它同时管"把人加载出来"和"腿有多快"，拆出 `gait.gd`（纯函数 + 一张速度表）后回到 314 行。
  400 行这条线不是形式主义：它每次都在"一个文件正要开始做两件事"时响。
- **这台笔记本有 GPU，但 agent 的运行环境看不到它**（2026-11-20 查清，以前写的是错的）。
  硬件：Intel HD Graphics 620（`i915`）+ AMD R5 M330（`amdgpu`），驱动都在正常加载。
  但 agent 的 shell 跑在一个被重新挂载过的命名空间里：`/dev` 是 4 MB 的 devtmpfs，
  `/dev/dri` 不存在，`mknod` 被拒（EPERM），跨 `/proc/1/root` 也看不到。
  → **agent 启动的任何 Godot 都只能走 llvmpipe 软件光栅，卡是必然的，与 debug/代码无关。**
  要让 GPU 生效，必须**由用户在桌面终端里跑** `./run.sh`；日志出现
  `Using Device: Mesa Intel(R) HD Graphics 620` 才算走对了。双显卡机器若仍卡，
  可试 `DRI_PRIME=1 ./run.sh` 走独显。
  推论：**agent 侧的一切帧时数字都只是环境噪声**，性能结论只能靠第 13 步的结构断言。
- **"帧时基线 6.90 ms" 曾经追了好几轮，它测的是环境**。空场景跑同样的循环也是
  6.90 ms —— 无头主循环自己有 ~6.8 ms 地板（实测最小 2~4 ms、最大 11~23 ms）。
  所以 `PERF 帧时` 那行只做参考；**红线在第 13 步的结构断言**。
  要真实帧率，只能去有 GPU 的机器或导出包上测。同理，改 CCD / contact_monitor
  这类物理开关时，光看帧时是看不出差别的（试过：关掉 CCD，帧时一模一样）。
- **材质现在按配色共用，就地改色必须先 `MESH_LIB.unshare()`**。忘掉这一步的症状是
  "给一个箱子染色，所有同色箱子一起变色"——功能全绿、无人报错、玩家只会觉得诡异。
  第 13 步有一条染色隔离断言守着它（去掉 unshare 会立刻 FAIL，已做负向验证）。
- **`PhysicsRayQueryParameters3D` 与 `Camera3D.get_frustum()` 都是每帧一次的东西**。
  试过按"射线参数相同"缓存射线结果，生成菜单探针立刻红：世界在同一帧内也会变
  （刚放下的柱子就落在射线里），而参数没变。**射线的答案属于"现在"，不能缓存结果。**
- **卡通着色的亮度是标定出来的，不是算出来的**。Compatibility 的 `LIGHT_COLOR` 与
  Forward+ 不同量级，`toon.gdshader` 里的 `light_gain` 是实测值。换渲染器必须重新标定。
- **自检只走到 Plan 层，不实例化玩家**。`player.gd` / `hands.gd` / `store.gd` /
  `ui/spawn_menu.gd` 的运行时错误 `check.sh` 第 5 步抓不到。所以有三道额外防线：
  `probes/save_roundtrip.gd`、`probes/spawn_menu.gd`、以及"改完真的跑一次窗口"。
- **`:=` 推不出类型时会 Parse Error，而编译期完全没提示**。`pack` 是 untyped 的，
  `var x := pack.some_bool()` 会炸在**加载这个文件的那一刻**（游戏或探针），
  而不是 `check.sh` 第 5 步。写 `var x: bool = ...`。
- **抓取的射线必须从角色胸口发出**，不能从相机。第三人称相机在身后 3.8 米，
  从相机发一条 3 米射线，走到头刚好停在角色后脑勺。
- **拉的是质心不是原点**。内容的原点在底面，把原点拉到胸口的结果是箱子浮在胸口。
- **撞击速度必须缓存上一物理帧**。`body_entered` 到达时接触已经解算完。
- **动态物体不合批**。想加大量可动物体之前，先想清楚提交次数。
- **静态物不是免费的**。它不参与模拟，但碰撞体永久占用物理查询，所以也计入
  `MAX_SPAWNED` 预算。
- **预算按节点身份记账，不是一个计数器**（`api._made`：instance_id → handle）。
  计数器记不住"哪几件是我造的"，于是拆掉的东西照样占额度，读一次档额度还会清零。
  读档恢复的东西必须 `api.adopt()` 认领回来，否则读档就是无限刷物的后门。
- **房间自带的障碍和玩家摆的柱子长得一模一样**，区别只在归属：前者在 chunk 里，
  后者在 `world.props` 里。`world.remove_thing` 只认后两个列表 —— 这就是
  "房间拆不掉"的全部实现。别把这条守卫改成"按 collider 是不是 static 判断"。
- **类型化数组的 `find` 会报错，但"刚好"返回 -1**。`bodies` 是 `Array[RigidBody3D]`，
  拿 `StaticBody3D` 去 `find` 会打一条引擎 ERROR 再返回 -1 —— 恰好落到正确分支。
  断言全绿、功能正确、日志每右键一次墙就脏一行。**先按类型分岔再 find**。
  这一类"刚好对"的实现最难发现，见下一条。
- **验收曾经只 grep 业务标记，于是引擎报错完全不可见**。现在 `no_engine_errors()`
  把 `^ERROR` 一律算失败（第 5/6/7 步都过一遍）。摘钩验证过一次：把上面那个
  `find` 的错误用法放回去，`MENU RESULT OK` 仍然打印，但验收红 —— 这就是它存在的理由。
- **`pass` 是 GDScript 关键字**，不能当变量名（`var pass := ...` 会 Parse Error）。
- **`run.sh` 的参数白名单**：`--trust=*` / `--selftest` / `--fresh` 要放进 `--` 之后。
  新加一个游戏参数必须同时改这里。
- **9 / 13 个内置组件被引擎读过**（model / collider / spawner / room / pickup /
  move / ai / health / loot）。剩下 4 个是死数据：`light` / `interaction` /
  `wieldable` / `transform`。骨行者不再是雕像 —— 会走、会死、会掉，
  但"开关门、举火把、拿武器"还是写不出来的。**另外还有 1 个 mod 声明的
  自定义组件（`pulse`），由声明它的 mod 系统自己读** —— 这条不占内置 13 个的额度，
  是 L4 开放度，不是引擎多实现了一个组件。
- **mod 的编译产物会过期，而且过期得很隐蔽**：`hard_mode` 的旧 `content.pack.json`
  里 `collider.dynamic` 还是 false，编译基础内容时新值刚写进去，**mod 合并又按 id
  覆盖回旧值** —— 怪变回雕像，全程没有任何报错。改契约/内容后必须重编 mod
  （`check.sh` 第 2 步就是干这个的，本地只跑单个探针不算数）。
- **视锥判据的正负号写反不报错**：Godot 的视锥平面法线朝外，点在视野内时
  `distance_to` 是**负**。取"最可能在外的顶点"还是"最可能在内的顶点"也容易搞反。
  写错的症状是"画 2 剔 17"或全画 —— 一切正常，只是该画的没了。
  所以剔除探针里有一条**与 Godot `is_position_in_frustum` 逐件对拍**，改剔除必看它。
- **绝对计数的断言会被内容变化打破**：存档探针曾写死 `bodies.size() == 14`，
  怪变刚体后红 —— 红的是断言不是功能。数量断言用"存档那一刻"的相对基准。
- **Godot 的 JSON 把所有数字读成小数**：编译产物里的 `48` 到运行时是 `48.0`。
  运行时校验器必须把"整数值的小数"当合法、把 `1.5` 这种假整数拒绝；
  否则无辜的 data mod 会被整包挡在门外（本轮 `hard_mode` 真踩到）。
- **`:=` 用在 untyped 对象的返回值上会炸在加载脚本那一刻**：
  `var x := app.pack.extension_component_names()` 在无头下是 Parse Error，
  编译期完全没提示。L4 新增的 `pack` / `runner` / `ctx` 调用一律显式写类型。
- **L4 自定义状态不进存档**：`extension_state.gd` 按 handle 存在内存里，
  物体消失就清理。想让某个 mod 状态跨会话保存，必须单独设计版本迁移与卸载清理，
  不能顺手塞进 `slot0.json`（ADR 0011）。
- **mod 系统是固定节拍，不是每帧**：`period` 有下限，掉帧时一帧最多补一次。
  需要逐帧手感（输入缓冲、物理求解、动画状态机）的规则要收进引擎内置系统，
  不要靠把 `period` 调到 0 来抢主循环。
- **运行时编译 GDScript 的入口仍然只有 `scripts/mods/loader.gd`**：
  L4 系统脚本和事件脚本共用它，`system_api.gd` 不自己 `GDScript.new()`。
  `lint_arch.py` R7 会拦第二处注入点。
- **一个房间只能填一种东西**：`spawner` 是单组件，一个房间实体只能有一个。
  "墓厅地上散着骨符 + 6 只骨行者"这种内容今天写不出来。要修就改 `spawner`
  支持分组（`groups` 列表），趁内容还只有 3 个房间的时候改最便宜。
- **`set_pose` 的方向要下一帧才生效**：它改的是 arm 的旋转，相机的全局变换
  要等场景树下一帧才传播。**调完视角就同帧算落点，算的还是旧朝向的** ——
  东西放在"我以为在的地方"的旁边，射线却指向真正的地方。
  探针踩过：骨符放在落点上，收却收不到。规则：调视角一帧，用方向下一帧。
- **放和收之间隔着几帧 = 物理噪声**。刚体被传送后会被推开、滚走，
  隔 6 帧射线就可能落空，而那不是功能的问题。探针里放和收**同一帧**完成。
- **本地过、CI 红，几乎总是"本地有残留状态"**。踩过一次：第 1 步的编译器自测往
  `build/` 写日志，而 `build/` 是「编译内容」那一步才创建的，干净 clone 上必然失败。
  验证方式是 `rm -rf build && ./check.sh`。
- **探针截图只在有显示的本机产出**（`game/*.png` 已 gitignore）。CI 是无头的，
  拿不到视口纹理；"因为截不到图所以整条失败"会让这条检查被人删掉。
- **导出包未验证**：运行时 GDScript 编译（事件脚本 + L4 系统脚本）、资源覆盖与
  外部 glTF 加载都只在编辑器二进制上验证过。P6 前必须在 Linux / Windows 导出包里
  重测，尤其 `GLTFDocument.append_from_file()` 是否可用（ADR 0012 推翻条件之一）。
- **mod 无沙箱**：`OS.execute` 实测可执行。授权是唯一防线（ADR 0003/0008）。
- **mod 产物不进版本库**，`clone` 后要先跑 `./run.sh` 或 `./check.sh` 编一遍。
- **房间之间没有门**，走道只是空地；世界是一条直线排列的房间（ADR 0004）。
- **存档不含 mod 状态**。L4 自定义组件的运行时值只在内存里；存档里也不存 mod 的
  私有数据。mod 卸载后存档里它的东西会"找不到内容"，读档时会列出来。
- **`component_spec` / 内容 id 不能同名**：组件声明和具体实体共享内容 id 空间。
  `kinetics/repulsor` 同时做组件 id 与实体 id 时会被编译器拒绝；组件用
  `kinetics/repulsor_spec`，实体保留 `kinetics/repulsor`。
- **冻结刚体不会响应 `api.impulse`**：Godot 对 `freeze = true` 的刚体不积分冲量。
  验冲量的探针不能把目标冻结；应固定机关、清零目标速度并去掉重力阻尼，
  **等下一个物理帧**再读速度。同帧读到的仍是旧速度。
- **探针不能把第一个组件 / 第一个系统 / `contexts[0]` 拼成一组**：第二个 L4 系统
  出现后它们可能来自不同 mod。探针必须按系统 `reads` / `writes` 找组件，
  再从 `runner._mod_systems` 找同一系统的上下文。
- **"扔箱子砸怪会扣怪的血"尚未被验证**：`body_entered` 当前把撞击施加给信号绑定的
  自己，而不是 `other`；速度也是各自上一帧速率，不是相对速度。`actors.gd` 用人工
  `impacts.append` 验的是伤害结算链路，不是真实碰撞目标。做伤害 / 压力板玩法前
  必须先补 `other_handle` 与相对速度，否则会错怪玩法脚本。
- **纯资源 mod 没有 `content/` 时，`build_mod()` 的 pack 骨架必须有 `extensions`**：
  第一个纯资源包（`asset_demo`）出现时才发现 `pack["extensions"]` 无条件访问会
  `KeyError`。骨架要与 `build_pack` 产物同形，扩展裁剪用 `pack.get("extensions", {})`。
- **`GLTFDocument.generate_scene()` 造出的节点必须显式 `free()`**：它不在场景树里，
  不释放就退出时泄漏一串 RID / ObjectDB 实例，被 `no_engine_errors()` 判成引擎报错。
  临时探针先踩到，正式 `assets.gd::_load_gltf()` 也照做。
- **untyped `Array` 的元素不能用 `:=` 推类型**：`for d in [dir_a, dir_b]` 里
  `var meshes := d + "/assets/meshes"` 是 Parse Error，且只在加载探针那一刻炸。
  显式写 `var dirs: Array[String]` / `var meshes: String` / `var f: FileAccess`。
- **覆盖项的三角形数不能继续用契约规划值**：文件在 mod 目录里，编译期看不到它
  有没有被换掉；`plan` / `chunk` / `perf` 一律按 `ASSETS.triangles_of()` 实测算。
  自检对未覆盖项才做「契约 vs 实测」对拍，否则数字会骗人（888 → 832）。
- **资源覆盖只认 `.gltf` / `.glb` 且文件名必须是已有 mesh id**：拼错的名字不会被
  忽略，而是记进 `problems()` 判红 —— 静默失效比报错难查得多。
